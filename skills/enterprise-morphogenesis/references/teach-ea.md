# Teach EA to learn EA under morphogenesis

Teaching is part of the control mechanism (Section 6.3). A form people cannot navigate cannot regulate them.

## What changes for the EA function

No established practice disappears. Each stops producing descriptions and starts producing conditions (Section 11.3).

| Practice | Teach them to produce |
| --- | --- |
| Solution architecture | Graph position, local trajectory, provenanced exceptions; human-led dyads |
| Reference architectures | Generative rule-sets consumed by teams and agents |
| Patterns | Developmental rules with telemetry on failure |
| Platforms | Organizer function: enable rules, carry the resource function, landmark the Atlas |
| Capability planning | Projections over the graph, not a second ontology |
| Portfolio rationalization | Standing homeostasis, not a periodic purge |
| Boards | Fewer routine decisions; more target-form and irreversible cases |

The architecture team's products include ontology, graph, projections, architecture APIs, policy packs, fitness views, decision memory, and agent context. Give them owners and consumers.

## Curriculum, in order

1. **The bind:** why review queues fail under AI-compressed change (1.6, 8).
2. **The thesis:** EA as morphogenetic system; mechanisms not parts (5.1, 14).
3. **Target form:** strategy including remain-in-place (5.2, 5.3).
4. **Graph vs maps:** projections (5.4, 5.12).
5. **Executable loop:** invariants, sensing, provenance (7.7, 7.10).
6. **Bootstrap:** one closed loop (11.4).
7. **Integrity:** inspectability, independence, no capture theatre (5.11, 11.2).
8. **Gauge:** six dials, never a score (Table 4).

Use the specialists deck for architects. Use the wide-adoption deck for everyone else. Do not mix audiences in one sitting.

## Wide workforce (non-architects)

Tell them three things only:

1. There is an intended shape of the enterprise, including "keep being trusted / dominant / safe."
2. There is one living map and a few rules that run in the tools they already use.
3. If a rule blocks good work, they file an exception with an owner and an end date; they do not route around it.

Do not teach them ArchiMate as a prerequisite for participation.

## Coaching vs conditions

Influence remains necessary. It is not sufficient. If a concern repeats hundreds of times, encode it into the environment. Coaching without encoding is the documentation era with better workshops.

## Capture and safety

Architects can be captured too. Teaching must include: published principles with rationale, comparable treatment of similar decisions, recorded exceptions, and the right to challenge without retaliation. Architecture is not a veto police (11.2).
